# DSH Nacos AI

[中文](./README.zh-CN.md) · English

A [DeepSeek Harness (DSH)] plugin that connects DSH to **Nacos AI AgentSpec** and the **Nacos Skill marketplace**.

It provides a single Nacos settings page where users can authenticate, browse online AgentSpecs and Skills, inspect them on demand, and materialize selected content locally for DSH sessions.

> **Status:** experimental. The plugin targets the Nacos AI Console endpoints and DSH `0.1.5-rc` APIs used by this repository. Verify compatibility against your own Nacos and DSH versions before production deployment.

## Features

- Shared Nacos connection for AgentSpecs and Skills.
- Credential-safe login: connection metadata is stored in DSH Settings; the access token is stored in DSH Credentials; passwords are never persisted.
- On-demand browsing and download: no Nacos network request or preset write is made during plugin startup.
- AgentSpec support: reads generic Nacos instruction resources such as `AGENTS.md`, including resources emitted from official Nacos ZIP imports.
- Standalone Skill support: downloads Skill bodies from the Nacos Skill marketplace by locally approved Skill name.
- Local DSH policy: tool loaders, tool permissions, preset display names, instruction-resource selection, and Skill selection remain local to DSH and are never accepted from Nacos content.
- UI-based local policy editor at **Settings → Nacos → Full-access tool policy**.
- Atomic preset/Skill materialization and fail-closed validation for invalid Nacos responses.

## Architecture

```text
Nacos AI
  ├─ AgentSpec: generic metadata + AGENTS.md/instruction resources
  └─ Skill marketplace: standalone SKILL.md bodies
                 │
                 ▼
DSH Nacos AI plugin
  ├─ shared connection + credential token
  ├─ local policy (tool profile, mappings, approved Skill names)
  └─ on-demand local materialization
                 │
                 ▼
DSH Agent Presets and host-wide Skill provider
```

Nacos remains a generic publishing system. Do **not** put DSH-only fields such as Cordis loader rows, tool permissions, MCP URLs, commands, environment variables, tokens, passwords, or private keys in AgentSpecs or Skills.

## Install

### Build from source

```bash
pnpm install
pnpm check
pnpm test
pnpm pack:plugin
```

The tarball is generated by pnpm in the package directory. Install it into a DSH Web profile:

```bash
dsh plugin --profile web add /path/to/dsh-nacos-ai-0.2.0.tgz
```

Restart the DSH Web host, then open **Settings → Nacos**.

### Offline installation

See [Offline installation](./docs/offline-install.zh-CN.md).

## Configure Nacos

1. Open **Settings → Nacos**.
2. Save the Nacos Server URL, namespace, and API plane.
3. Sign in. The password is used only for the login request; DSH stores the resulting access token through its credential service.
4. In **Agent Presets**, load the online AgentSpec catalog and download a selected preset.
5. In **Skill marketplace**, load and download standalone Skills when needed.

## Local policy

The plugin intentionally does not let a remote AgentSpec grant tools or permissions. Configure local policy under **Settings → Nacos → Full-access tool policy**:

- **Tool profiles JSON** defines local Cordis loader rows.
- **Preset mappings JSON** chooses a local tool profile, instruction resources, and standalone Skill names per AgentSpec.

A mapping example:

```json
{
  "example-agent": {
    "toolProfile": "full-access",
    "instructionResources": ["AGENTS.md"],
    "skillReferences": ["example-skill"]
  }
}
```

See [Configuration reference](./docs/configuration.md) and [Security model](./docs/security.md).

## Nacos publishing model

Publish standalone Skills first, then publish AgentSpecs which only refer to Skill names. An AgentSpec should contain generic metadata and instruction resources; a Skill should contain a complete `SKILL.md` body.

See [Nacos authoring guide](./docs/nacos-authoring.md).
